# Technology understanding evaluation

The separate fixed dataset `evaluation/technology-heldout.mjs` contains **140 explicitly written queries**: 40 direct entity, 30 alias/paraphrase, 30 category, 20 cross-project and 20 negative/ambiguous. Queries are not generated from registry aliases or approved answer text. Entity names necessarily appear in technology questions. Expected entity/project labels are separate from runtime rules. This agent-authored development set was inspected while implementing the resolver; it is not a blind holdout or independently owner-reviewed evaluation.

Run `npm run eval:technology`. Machine summary and per-question answers/errors are `evaluation/reports/toer-understanding-v1.json` and `toer-understanding-cases-v1.json`. The dataset hash, ontology version, evidence version/hash, timestamp and methodology are recorded. The evaluator uses pure local retrieval/composition, with no network/embedding/provider dispatch. Browser request observations are a separate check.

Observed after corrections: **140/140** exact expected entity sets, **140/140** expected project sets (including empty sets for negatives), **140/140** structured-answer/abstention outcomes, **20/20** appropriate negative abstentions, **0** invented project fact tuples, **0** invalid citations and **0** Workers AI calls. Coarse category checks cover **80 recognized-entity occurrences**, all matching independently specified expected categories. Supported association/answer denominators are 120 positive queries; their results are also available by group. The 95% category/association targets are met on this development sample only; no general accuracy guarantee follows.

The first run found unsupported exclusive wording (“only ECS”) and omitted browser-automation vocabulary. The resolver now abstains on exclusivity and recognizes the testing category. The reverse-proxy label was clarified to select the registered Nginx role instead of treating every web server as a reverse proxy. The final labeled dataset and all case outcomes remain inspectable. These development corrections are a reason not to call the sample unseen certification.

Citation checks establish registry membership, current scope/version/hash and source correspondence. A second guard compares each resolver fact tuple with the approved project-fact set. Those checks do not replace independent semantic entailment review. Tests separately cover unknown technologies, TypeScript non-inference, React/Next direction, EC2/ECS/Kubernetes separation, PDO/PHPMaker classifications, generations, source expiry, altered upstream hashes and cross-scope injection.

The historical embedding ranking baseline and the separated-view semantic evaluation remain distinct. A successful deterministic technology suite does not fix every semantic miss, prove real-user comprehension or verify live-generation grounding. See [TOER QA](PACE-RAG-TOER-QA.md) for actual browser/performance results and remaining gates. Release acceptance remains false.
